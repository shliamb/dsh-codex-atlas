# MEMORY.md — Atlas

## Обзор

`dsh-codex-atlas` — плагин DSH для Spec-Driven Development: единая карта проекта в `MEMORY.md`, строгая локальная спецификация `SPEC.md` в каждой папке модуля и общий журнал `JOURNAL.md`.

## Модули

- [Плагин dsh-codex-atlas](src/SPEC.md) — System Prompt, четыре инструмента, структуры MEMORY/SPEC/JOURNAL, миграция.

## Логические цепочки (Scenarios)

### Старт сессии

Плагин собирает System Prompt и внедряет карту проекта.

**Шаги:** `apply` ([src/SPEC.md](src/SPEC.md)) -> чтение `MEMORY.md` -> проверка структуры -> внедрение правил Atlas и содержимого карты (или инструкции `init`/`migrate`).

### Изменение кода

Агент находит модуль, читает его спецификацию и фиксирует изменение.

**Шаги:** `MEMORY.md` -> `SPEC.md` нужного модуля -> правка кода -> `update_spec` ([src/SPEC.md](src/SPEC.md)) -> `update_memory` при изменении карты/Roadmap -> `log_session` в конце сессии.

Вариант: если папки модуля ещё нет в карте — сначала создать `SPEC.md` и добавить модуль через `update_memory`.

### Миграция старого MEMORY.md

Старый файл от другого плагина никогда не перезаписывается молча.

**Шаги:** `sync_atlas` (`check`) -> вопрос пользователю -> при разрешении `sync_atlas` (`migrate`, `confirm=true`) -> резервная копия в `.atlas/backup/` -> сканирование проекта -> заполнение разделов через `update_memory` и `update_spec`.

Вариант: если структура уже Atlas, `migrate` ничего не меняет.

## Ограничения (Rules)

- Никаких сетевых запросов и дочерних процессов: только локальные файлы.
- `JOURNAL.md` не внедряется в System Prompt и не читается агентом без явной необходимости.
- `SPEC.md` — только статика; журналы и хронология в нём запрещены.
- Чужой `MEMORY.md` нельзя перезаписывать без явного подтверждения пользователя.
- Ноль runtime-зависимостей: в `lib/index.js` только `node:fs` и `node:path`.

## Стиль пользователя (User Style)

- Документация и сообщения для пользователя — на русском; код и идентификаторы — на английском.
- Минимум контекста: карта проекта короткая, без хронологии; журнал — отдельно.
- Любое изменение логики или формата данных фиксируется в `SPEC.md` в той же сессии.
