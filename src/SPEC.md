# SPEC: Плагин dsh-codex-atlas (Atlas)

## Суть работы

Плагин реализует Spec-Driven Development для DSH: держит единую карту проекта в `MEMORY.md`, статическую спецификацию каждого модуля в `SPEC.md` и общий append-only журнал `JOURNAL.md`. Плагин внедряет карту в System Prompt, даёт агенту четыре инструмента для поддержания файлов в актуальном состоянии и защищает старый `MEMORY.md` от молчаливой перезаписи.

## Входные данные

**Тип:** Cordis `Context` с сервисами `tools` и `systemPrompt`; аргументы инструментов (JSON).

**Формат:** `apply(ctx)` вызывается загрузчиком; инструменты принимают объекты:

```json
{ "section": "roadmap", "content": "- [x] ...", "mode": "append" }
```

```json
{ "module": "src/auth", "section": "input", "content": "..." }
```

```json
{ "module": "auth", "summary": "Добавлена проверка JWT" }
```

```json
{ "action": "migrate", "confirm": true }
```

`module` для `update_spec` — папка модуля или путь к `SPEC.md` внутри рабочей директории сессии. `section` для `update_memory` — один из `overview | modules | scenarios | roadmap | rules | style`; для `update_spec` — `purpose | input | output | logic | errors`.

## Выходные данные

**Тип:** зарегистрированные инструменты `update_memory`, `update_spec`, `log_session`, `sync_atlas`; секция System Prompt `dsh-codex-atlas:atlas`; изменения локальных файлов.

**Формат ответа инструмента:**

```json
{
  "ok": true,
  "path": "/project/MEMORY.md",
  "message": "Updated ## Roadmap.",
  "content": "Updated ## Roadmap in MEMORY.md."
}
```

Модель видит `content`, если он непустой, иначе `message`. `update_*` в режиме чтения возвращают содержимое файла; в режиме записи — короткое подтверждение, чтобы не тратить токены на эхо.

## Логика (Вариации)

- **`update_memory` без аргументов** — прочитать `MEMORY.md`. Если структура чужая, вернуть предупреждение и содержимое, но не писать.
- **`update_memory` + `module` + `spec`** — проверить, что `SPEC.md` существует, и добавить строку в `## Модули`. Дубликат по ссылке не добавляется.
- **`update_memory` + `section` + `content`** — заменить секцию; при `mode: "append"` — дописать в конец секции. Если секции нет, она создаётся в конце файла.
- **`update_memory` при `MEMORY.md` чужой структуры** — отказать; сначала `sync_atlas` с `action: "migrate"` и подтверждением пользователя.
- **`update_spec` без `section`** — прочитать `SPEC.md`. Если файла нет — вернуть ошибку с подсказкой.
- **`update_spec` + `section` + `content`** — создать `SPEC.md` из шаблона при отсутствии, затем заменить/дополнить секцию. Шаблон подсказывает тип, формат и пример для входов/выходов. Существующий текст не удаляется.
- **`log_session`** — дописать ровно одну строку `[YYYY-MM-DD HH:MM] [Модуль] Итог` в `JOURNAL.md`.
- **`sync_atlas` `check`** — только отчёт: состояние `MEMORY.md`, наличие `JOURNAL.md`, число `SPEC.md` и невалидных спецификаций. Ничего не пишет.
- **`sync_atlas` `init`** — создать отсутствующие `MEMORY.md`/`JOURNAL.md`. Чужой `MEMORY.md` не трогает.
- **`sync_atlas` `migrate` + `confirm: true`** — сохранить копию старого `MEMORY.md` в `.atlas/backup/`, добавить недостающие канонические заголовки, сохранив весь старый текст, и создать `JOURNAL.md`.
- **Завершение сессии** — если агент не вызвал `log_session`, плагин дописывает в `JOURNAL.md` одну автоматическую строку с модулем `atlas`. Для subagent-сессий автозапись не выполняется.

System Prompt всегда содержит компактные правила Atlas. Если `MEMORY.md` в порядке, его содержимое внедряется под заголовком `### MEMORY.md` (не более 6000 символов). `JOURNAL.md` в контекст не внедряется никогда.

## Обработка ошибок

- Нет рабочей директории у сессии — инструмент возвращает `ok: false` с пояснением, файлы не трогаются.
- `MEMORY.md` отсутствует или имеет чужую структуру — запись через `update_memory` отклоняется; возвращается инструкция вызвать `sync_atlas`.
- `migrate` без `confirm: true` — отказ, файлы не меняются.
- `SPEC.md` не найден, путь выходит за пределы рабочей директории, указывает в `node_modules`/`.git` или не называется `SPEC.md` — возвращается `ok: false`.
- Ошибки файловой системы перехватываются и возвращаются как `ok: false`; плагин не роняет сессию.
- Ошибка автозаписи журнала при завершении сессии логируется предупреждением и не влияет на завершение.
